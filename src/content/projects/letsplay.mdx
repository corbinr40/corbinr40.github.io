  <FeatureSection title="Features">
    <p>LetsPlay grew out of a frustration familiar to anyone with more than one console: checking four different stores, in four different currencies, to find out which platform has the best deal on a game this week. Rather than keep doing that manually, I built the thing that does it for me.</p>
    <ul>
      <li>Search across PS Store, Xbox, Steam, and Nintendo Switch in one place</li>
      <li>Real-time pricing with automatic multi-region currency support</li>
      <li>Subscription tier awareness so Game Pass and PS Plus availability shows up alongside sale prices</li>
      <li>IGDB-powered canonical game registry to handle the "is this the same game?" problem across platforms</li>
      <li>Watchlists and price drop notifications</li>
    </ul>
  </FeatureSection>
</div>

<div className="section-wrapper">
  <FeatureSection title="Why IGDB as the Canonical Registry">
    <div className="textContainer">
      <p>One of the hardest parts of this project wasn't scraping prices, it was agreeing on what counts as "the same game" across storefronts. The PlayStation Store calls it "Hitman 3 Standard Edition". Xbox calls it "HITMAN 3". Steam calls it "HITMAN World of Assassination" because they bundled two sequels into one package. Nintendo's version is the cloud-only edition and has a different title again.</p>
      <p>Rather than build my own fuzzy-matching logic, I leaned on IGDB (Internet Game Database) as the source of truth. Every store entry gets matched to a canonical IGDB record, which means prices, platforms, and regions all key off a single stable ID. That decision alone saved weeks of edge-case handling.</p>
    </div>
  </FeatureSection>
</div>

<div className="section-wrapper">
  <FeatureSection title="The Stack">
    <p><b>Frontend:</b></p>
    <ul>
      <li>React Native with TypeScript for iOS, Android, and Web (single codebase)</li>
      <li>Local state with React Query for server cache management</li>
    </ul>
    <p><b>Backend:</b></p>
    <ul>
      <li>Python (FastAPI) for the public API</li>
      <li>TimescaleDB for price history, chosen specifically for time-series compression and efficient range queries</li>
      <li>PostgreSQL for everything else (users, watchlists, game metadata)</li>
      <li>Scheduled scrapers (see the PS and Xbox Web Scraper project) feed the database nightly</li>
    </ul>
    <p><b>Infrastructure:</b></p>
    <ul>
      <li>AWS (EC2 for the API, RDS for Postgres, S3 for static assets)</li>
    </ul>
  </FeatureSection>
</div>
