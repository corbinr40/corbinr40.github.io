    <div className="textContainer">
      <p>The firmware is written in <b>C</b> using Espressif's <b>ESP-IDF</b> framework. It implements the standard Zigbee thermostat cluster, which means Home Assistant discovers the device natively without any custom integration or MQTT bridge.</p>
      <p>Key firmware responsibilities:</p>
      <DescList items={[
        { term: "Zigbee thermostat cluster", desc: "implements the ZCL thermostat cluster for native HA discovery and control" },

        { term: "Display multiplexing", desc: "real-time Charlieplex multiplexing to drive the 7-segment display" },
        { term: "Network management", desc: "Zigbee network join and rejoin logic with persistent state across power cycles" },
        { term: "Power management", desc: "deep sleep between polling intervals to minimise power draw on the mains supply" },
      ]} />
    </div>
  </FeatureSection>
</div>

<div className="section-wrapper">
  <FeatureSection title="Zigbee & Home Assistant Integration">
    <div className="textContainer">
      <p>One of the core design goals was <b>zero cloud dependency</b>. The device joins the local Zigbee network directly via a Zigbee coordinator (such as a Sonoff Zigbee 3.0 USB Dongle Plus) and is discovered by Home Assistant's built-in Zigbee Home Automation (ZHA) integration.</p>
      <p>Once paired, it exposes the following entities in Home Assistant:</p>
      <ul>
        <li>Current temperature (read from onboard sensor)</li>
        <li>Target temperature setpoint (controllable via HA or the physical dial)</li>
        <li>Thermostat mode (heat / off)</li>
      </ul>
      <p>All control is local - no internet connection required, no vendor servers involved.</p>
    </div>
  </FeatureSection>
</div>
