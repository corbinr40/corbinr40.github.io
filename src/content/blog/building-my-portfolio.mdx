<div className="section-wrapper">
  <FeatureSection title="The Stack">
    <p>The site is built with <b>React 19</b>, <b>TypeScript</b>, and <b>Bootstrap 5</b>, bundled with <b>Vite</b>. Content is written in <b>MDX</b>, which is basically Markdown that has learned how to host React components inside itself. It sounds like overkill until you try to put an image carousel into a blog post and realise plain Markdown wants no part of that.</p>
    <p>Everything is hosted on <b>GitHub Pages</b> and deployed automatically when I push to main. No server, no database, no surprise bills at the end of the month.</p>
  </FeatureSection>
</div>

<div className="section-wrapper">
  <FeatureSection title="The Content System">
    <p>The original version of this site had every project page as its own hand-written React component. It worked, but it meant that adding a new project was a four-file job: a new page component, a new route, a new entry in the data file, and usually some CSS tweaks. Not hard, just annoying enough that I kept putting off writing new projects.</p>
    <p>The rebuild swapped all of that out for a single pattern: every project and blog post is one <code>.mdx</code> file. The top of the file has YAML frontmatter (title, date, tags, that kind of thing) and the rest is MDX, which means I can drop in React components wherever I want. A content registry picks up every <code>.mdx</code> file at build time and wires up routing automatically. Adding a new project is now a one-file job. Writing this post took longer than the code would have.</p>
    <p>The system supports ten different content block types out of the box:</p>
    <ul>
      <li>Hero sections with an image and intro text</li>
      <li>An automatic overview table that reads from frontmatter</li>
      <li>Feature sections (basically "heading + content", the workhorse block)</li>
      <li>Image carousels for showing off multiple shots</li>
      <li>Image-with-paragraph layouts (left or right aligned)</li>
      <li>Code blocks with syntax highlighting</li>
      <li>Video embeds for YouTube and Vimeo</li>
      <li>Callout boxes for info, warnings, or tips</li>
      <li>Pull quotes for when you want to be dramatic</li>
      <li>Description lists for term-and-definition content</li>
    </ul>
  </FeatureSection>
</div>

<div className="section-wrapper">
  <FeatureSection title="The Editor">
    <p>At this point I should have stopped. The MDX system worked. I could write new posts. Job done.</p>
    <p>Instead, I built a full block-based editor at <code>/editor</code>. It works a bit like Notion or WordPress Gutenberg: drag-and-drop blocks, a rich text editor on top of TipTap, live preview using the actual site components, image uploads, draft management with auto-save to IndexedDB, and the ability to publish directly to my GitHub repo via the Contents API. When I hit "Publish" on a new post, it creates a commit, pushes it, and GitHub Actions redeploys the site. End to end, writing and shipping a post takes about as long as it takes to drink a coffee.</p>
    <p>The editor is lazy-loaded and hidden from search engines, so regular visitors pay no cost for its existence. But it's there if I need it, and it's saved me from the traditional blogger's dilemma of "I have a thing to write about but I can't be bothered to open my IDE to do it".</p>
  </FeatureSection>
</div>
