Real Time Communication Captions (RTCC)

RTCC, or Real Time Communication Captions, is a piece of software that converts voice to text in a visual output, as an aid to individuals who are hard of hearing. The plan is to deliver this via a piece of hardware in the form of glasses with a heads up display. However a fallback of this would be an app that fulfils this. The system will work by using facial detection to track who is talking to place the converted audio appropriately.

Features

Before we started this project we set ourselves some goals that we needed to adhere by when developing. These are the goals:

  • The application can work offline,
  • The application can work from a single device (no extra hardware to offload processing power),
  • Everything was self contained to reduce the number of attacks on the system when in use.

    • RTCC is broken down into 4 main areas: audio, visual, UI, and hardware. The audio component focuses on taking audio in from the user, processing it and then outputting, along with handling audio commands for system processes. The visual component will use a camera to look for a face, detect where it is and pass the data onto the UI. The UI handles all of the aspects which the user sees and interacts with. Finally, the hardware component is making sure all of the software works efficiently and cohesive with one another.

    Usage

    RTCC was designed to work with a Raspberry Pi Zero W 2, but we did test it on Windows and MacOS

    The program is intended for use with voice commands, but does have them bound to keys for debugging/use without microphone

    Much like smart assistants, to activate/interact with the device you need to state a wake word. The word we chose was "Armadillo". The reason this word was chosen was due to it being apart of our group name (Ominous Armadillos).

    When you want to say a command, it follows the same structure that most are familiar with:
    <wake word> <state> <command>
    eg: armadillo activate face detection
    or
    <wake word> <command> <state>
    eg: armadillo set Font Colour to Red

    The full list of commands are:

  • face detection - Activate/Deactivate face detection
  • voice detection - Conversation Start/Stop
  • settings - Show settings
  • commands - Show command list
  • shut down - Close program
  • set font colour red - Set font colour to Red
  • set font colour green - Set font colour to Green
  • set font colour blue - Set font colour to Blue
  • set font colour white - Set font colour to White
  • increase font size - Increase font size
  • decrease font size - Decrease font size

    • Key combines
    All are case-sensitive
    System Wide
  • o - Activate/Deactivate face detection
  • p - Activate/Deactivate voice detection
  • s - Show settings
  • c - Show command list
  • escape - Close program

    • Settings only
  • P - Set font colour to Red
  • O - Set font colour to Green
  • I - Set font colour to Blue
  • U - Set font colour to White
  • + - Increase font size
  • - - Decrease font size

    Visual

    The visual component is a custom Machine Learning Model trained on Flickr-Faces-HQ Dataset (by NVLabs) and further with MaskedFace-Net dataset. The ML model was developed, unintentionally, in 2 parts. The first being trained on (NUMBER) of images. An issue with this was that the ML model could not detect people who were wearing a mask, as this idea stemmed from 2020 lockdown due hearing that people who are hearing impared would be unable to lipread due to the masks. This then stemmed the further ML development by including masked faces in the training data. This opened our eyes on the faults with ML model, by over teaching a model causing it to ultimately fail.
